# WB + Ozon Google Sheets / Apps Script

Новая самостоятельная версия системы управления магазинами Wildberries и Ozon.

## Принципы проекта
- Не зависит от `bmaks98/api-wb` и действующей таблицы.
- Не содержит токенов, ID таблиц и данных магазинов.
- Поддерживает WB, Ozon или оба маркетплейса.
- Отправка цен, остатков и управление акциями по умолчанию выключены.
- Один физический склад — источник фактического остатка.
- Создание карточек — с листа `Новые карточки`, фото хранятся прямо в ячейках.

## Текущий этап — dev8
Уже реализованы:
- установщик структуры из 16 листов;
- настройки, безопасное хранение API-ключей, регламенты, журнал и email-уведомления;
- импорт каталогов WB/Ozon, единый склад и сопоставление артикул → штрихкод → название;
- обработка FBS-заказов: немедленное списание фактического остатка и возврат при отмене до отправки;
- синхронизация фактического остатка на WB/Ozon под защитным переключателем;
- расчёт цен по маржинальности с приоритетом товар → категория → значение по умолчанию;
- отдельные режимы `Авто / Ручной` для WB и Ozon;
- получение текущих цен, комиссий и логистических расходов через API;
- отправка цен WB/Ozon под защитным переключателем;
- защита от массовой аномалии цен: при массовом изменении >40% регламент останавливается защитой;
- загрузка и оценка акций WB/Ozon по минимально допустимой маржинальности;
- автоматический вход во все доступные прибыльные акции;
- автоматический выход из убыточных акций Ozon через deactivate;
- безопасный выход из обычных акций WB через повышение базовой цены только для режима «Авто»; ручная цена WB не изменяется;
- массовая защита управления акциями: массовый выход/аномально большой объём изменений останавливает регламент;
- единый дашборд WB / Ozon / Общий по финансово реализованным операциям;
- WB: актуальный Finance API `/api/finance/v1/sales-reports/detailed`;
- Ozon: актуальные `/v1/finance/accrual/by-day`, `/v1/finance/accrual/types` и `/v1/finance/accrual/postings`;
- метрики: выручка, реализовано, себестоимость, комиссии, логистика, прочие удержания, чистая прибыль, маржинальность, средний чек, возвраты, стоимость и количество текущего склада;
- сравнительный временной ряд по дням (период <31 дня) или месяцам и 4 сравнительных графика;
- товарные блоки: ТОП по выручке, прибыли, количеству, низкая маржинальность и товары без продаж.
- Ozon: итог чистых начислений сверяется по `total_amount`, поэтому в прибыль попадают ITEM/NON_ITEM, эквайринг, компенсации и новые типы удержаний;
- заказы не используются как продажи: количество Ozon берётся из финансовых `accrual/postings`, WB — из отчёта реализации;
- дополнительных финансовых листов не создаётся: структура проекта остаётся из утверждённых 16 листов.

Для WB расчёт использует FBS-комиссию предмета из `/api/v1/tariffs/commission` и расчётную логистику по текущим коробочным тарифам. Для Ozon комиссия и FBS-логистика берутся из `/v5/product/info/prices`.

Для Ozon модуль цен и модуль акций используют один и тот же рассчитанный безопасный предел цены. Это учитывает введённую в октябре 2026 единую предельную цену Ozon и не позволяет двум регламентам циклически перезаписывать разные значения.

Ограничение WB: API календаря не предоставляет список кандидатов для автоакций, поэтому такие акции фиксируются в журнале как недоступные для автоматического подбора. Обычные календарные акции управляются полностью.

- прогноз закупок по финансово реализованным продажам WB/Ozon за 30 / 60 / 90 / 360 дней или пользовательский период;
- отдельные продажи/средние продажи WB, Ozon и общий итог, доли маркетплейсов;
- сезонность Ks по месяцам с усреднением одинаковых месяцев при наличии нескольких лет истории;
- срок поставки и закупочный буфер `Запас, дней` влияют на момент заказа, но не резервируют остаток маркетплейсов;
- активные заказы поставщикам учитываются как уже заказанный товар, отдельно показывается товар со статусом `В пути`;
- создание заказа поставщику вручную или из отмеченных строк прогноза через диалог;
- частичная и полная приёмка поставки с вариантами себестоимости: не менять / заменить / средневзвешенная;
- после приёмки увеличивается `Фактический остаток`, а при разрешённой автоматике остатки отправляются на подключённые маркетплейсы.

- создание новых карточек WB/Ozon с единого листа `Новые карточки`;
- справочники `Предмет WB` и `Тип товара Ozon` с человекочитаемыми значениями и скрытыми техническими ID;
- подстановка предмета/типа через лист `Категории` и сохранение ручного сопоставления;
- динамическая загрузка только обязательных характеристик для выбранных предметов/типов;
- фото 1–10 читаются непосредственно из изображений в ячейках Google Sheets;
- предвалидация без отправки, генерация внутренних ID и EAN-13-подобных штрихкодов;
- независимое создание на WB и Ozon: успех одной площадки сохраняется при ошибке второй;
- WB: асинхронное создание `/content/v2/cards/upload`, последующее получение nmID и бинарная загрузка фото из ячеек через `/content/v3/media/file`;
- Ozon: `/v3/product/import` + отслеживание `task_id` через `/v1/product/import/info`;
- стартовая цена передаётся из листа `Новые карточки`, первоначальный фактический остаток всегда 0;
- после создания товар автоматически добавляется/обновляется в `Склад` и `Сопоставление товаров`;
- повтор ошибочных карточек сначала проверяет уже созданный товар и не дублирует успешную отправку.

Все крупные функциональные модули утверждённого v1 реализованы. Следующий этап — интеграционное тестирование, миграции и полировка установки/UX.

## Установка
1. Создайте пустую Google-таблицу.
2. Откройте **Расширения → Apps Script**.
3. Загрузите файлы из папки `src` (удобнее через clasp).
4. Запустите `installProject()` один раз и выдайте разрешения.
5. Вернитесь в таблицу и обновите страницу.
6. На листе `Начало работы` пройдите шаги по порядку.
7. На листе `Настройки` вставьте API-данные и выполните **Настройки → Сохранить API-ключи**.
8. Проверьте подключения.
9. Выполните **Настройки → Обновить список складов** и выберите склад, если их несколько.
10. Импортируйте каталог и проверьте сопоставление.
11. Заполните фактические остатки.
12. Для создания карточек загрузите справочники WB/Ozon, настройте сопоставления на листе `Категории` и при необходимости задайте `Бренд по умолчанию`.
13. Только после проверки включите защитное разрешение на отправку остатков и нужные регламенты.

## Безопасность API-ключей
API-ключи вводятся на листе `Настройки`, затем командой сохраняются в Script Properties. После сохранения значения в ячейках маскируются. В репозитории ключи не хранятся.

## Репозиторий
Этот проект является отдельной версией. Исходный `bmaks98/api-wb` не изменять.
